Bubble, Insertion & Selection Sort

A calm study sheet. No ready-made Java code here on purpose — just the idea, a hand-worked example, and a playground so you can rebuild each algorithm from understanding.

3 algorithms · one playground hand-trace first, code second ~15 min read

The shared starting point

All three sort an array in place (no second array) by repeatedly comparing elements and moving them. They differ only in what they look for on each pass.

AlgorithmEach pass does…Picture it as…
BubbleFixes adjacent pairs; the biggest unsorted value “bubbles” to the end.Bubbles rising to the surface.
InsertionTakes the next card and slides it left into the already-sorted hand.Sorting playing cards in your hand.
SelectionFinds the smallest in the unsorted part and puts it at the front.Picking the shortest student to the front of a line.

Convention below: n = array length, indices 0 … n−1. “Pass” = one full sweep that places one element in its final spot.

Bubble Sort — fix neighbours, biggest floats right

One-line idea: walk left → right, compare each pair of neighbours, swap if they are in the wrong order. After one full walk, the largest value is guaranteed at the far right.

How to think about it

  1. Look at positions j and j+1.
  2. If a[j] > a[j+1], they are inverted → swap. Otherwise leave them.
  3. Move one step right and repeat until the end. That is pass 1; the last slot is now final.
  4. Repeat, but stop one slot earlier each time (the tail is already sorted).
  5. Early exit: if a whole pass makes zero swaps, the array was already sorted — stop.

Idea sketch (not Java — write that yourself)

# n = length. Outer pass shrinks the inner walk.
for i from 0 to n-2:
    swapped = false
    for j from 0 to n-2-i:      # stop before the sorted tail
        if a[j] > a[j+1]:
            swap a[j] and a[j+1]
            swapped = true
    if swapped is false: break   # already sorted

Hand-worked example

Array: [5, 1, 4, 2, 8]. Watch the biggest value drift right each pass.

Remember: after pass k, the last k slots are final. That is why the inner loop ends at n−2−i. Off-by-one here is the #1 bug — trace it with 3 elements on paper.
Common mistake: forgetting the array is already sorted and doing all passes anyway. The swapped flag turns best-case into a single linear scan.

Facts

Comparisons ≈ n²/2 · Swaps: many (worst n²/2) · Best O(n) with flag, else O(n²) · Space O(1) · Stable (equal items keep order, because you only swap on strict >).

Insertion Sort — grow a sorted hand, insert each new card

One-line idea: the left side is always sorted. Take the next unsorted card (key) and shift bigger cards right until you find its home.

How to think about it

  1. Element 0 alone is trivially sorted. Start with the element at index 1 as key.
  2. Compare the key with the element to its left. If that element is bigger, shift it one slot right (not a swap — a slide).
  3. Keep shifting left until you meet a smaller-or-equal element or run out of room.
  4. Drop the key into the gap. The sorted region just grew by one.
  5. Move to the next key and repeat.

Idea sketch (not Java — write that yourself)

# left of i is already sorted
for i from 1 to n-1:
    key = a[i]
    j = i - 1
    while j >= 0 and a[j] > key:
        a[j+1] = a[j]   # shift right, opening a gap
        j = j - 1
    a[j+1] = key        # place key in the gap

Remember: it shifts, not swaps. Save the key in a variable first, or you overwrite it. Ask yourself: “where did my key go while I shift?”
Common mistake: writing a[j] = a[j+1] (wrong direction) or losing the j+1 when j becomes −1. Trace the 5 step above with your finger.

Facts

Best O(n) (already sorted — inner loop never runs) · Worst O(n²) · Space O(1) · Stable · Excellent for small or nearly-sorted arrays. This is why it is often used as the base case inside faster sorts.

Selection Sort — find the smallest, put it in front

One-line idea: divide the array into sorted (front) and unsorted (rest). Each pass scans the whole unsorted part for its minimum and swaps it into the boundary position.

How to think about it

  1. Boundary starts at index 0. Everything right of it is “unsorted”.
  2. Scan from boundary → end, remembering the index of the smallest seen so far (minIdx).
  3. After the scan, one swap: put a[minIdx] at the boundary (skip if it is already there).
  4. Move the boundary one step right. That slot is now final.
  5. Repeat. Exactly n−1 passes, at most one swap per pass.

Idea sketch (not Java — write that yourself)

# i is the boundary between sorted | unsorted
for i from 0 to n-2:
    minIdx = i
    for j from i+1 to n-1:
        if a[j] < a[minIdx]:
            minIdx = j      # found a new smallest, remember it
    if minIdx != i:
        swap a[i] and a[minIdx]

Remember: compare against a[minIdx], not against a[i] every time — otherwise you swap repeatedly instead of once. One scan, one swap.
Common mistake: swapping inside the inner loop (that turns it into a worse bubble). The swap belongs after the inner loop finishes.

Facts

Always ≈ n²/2 comparisons — even on sorted input (no early exit) · Swaps: at most n−1 (few!) · Space O(1) · Not stable (a distant swap can jump over equals) · Good when swaps are expensive.

Quick self-check (answers hidden)

After ONE full bubble pass on [4, 3, 2, 1], what is the array?

[3, 2, 1, 4]. Only the largest is guaranteed placed — the rest is still unsorted. The sorted tail grows from the right.

Insertion sort on [2, 3, 4, 5, 1] — how many positions does the key 1 shift?

Four. Every element shifts right and 1 lands at index 0. This shows insertion sort’s worst case for a tiny element at the end.

Why does selection sort always do ~n²/2 comparisons?

It must scan the entire unsorted region to prove it found the minimum. There is no early exit — sorted input costs the same as random input.

Which two are stable, and why does it matter?

Bubble and insertion (with strict >) keep equal items in original order. Selection can leapfrog equals with a long swap. Stability matters when sorting records by one key while preserving a previous order.
